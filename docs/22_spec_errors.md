# Спека: обработка ошибок внешних источников

База анализа — каталог ошибок 1–235 (файлы 17–21). Здесь зафиксированы политики, по которым эти ошибки обрабатываются.

> **Обновлено по решениям владельца** ([`25_contradictions.md`](25_contradictions.md), раздел 0.1): `~~отменено~~` — правила, которые в MVP **не реализуются**.
> Главное: **circuit breaker отсутствует** (ADR-VL-04), 403/429/503 **не ставят источник на паузу** (ADR-011/016), ошибка источника всегда упоминается в тексте ответа, метрики свои (без Prometheus, ADR-VL-06), anti-bot не обходим (ADR-VL-12).

## Инвариант

> Любой анхэппи путь внешнего источника заканчивается либо понятным сообщением пользователю,
> либо частичным результатом. Ни одна ошибка источника не роняет всю сессию.

## Уровни обработки ошибок

Каждая ошибка ловится на своём уровне, вышестоящий слой не знает о деталях нижестоящего:

```
IOException / из сети
   → *ClientException            (OkHttp: карта кода/типа → исключение клиента)
   → *ServiceException           (Service: бизнес-ошибка источника)
   → Tool                        (ловит, логирует, возвращает пустой список / partial + errorCode)
   → Combiner / Ranker           (пустые и partial источники пропускаются)
   → LLM summary                 (упоминает только доступные источники)
```

Правила:
- **Источник изолирован**: падение одного не влияет на другие (параллельные инструменты, каждый со своим клиентом).
- **Тип исключения сохраняется** до метрик: `source.errors{source="atlas", type="500"}`.
- **partial-результат** (`partial=true`, `timeout=true`) — это не ошибка: то, что успело собраться, доходит до пользователя.

## Карта: тип ошибки → действие по умолчанию

| Тип ошибки | Поведение |
|---|---|
| 500, 502 | Пустой список от источника, остальные источники работают |
| 503 + `Retry-After` | [ВЛ] **Немедленная ошибка источника, без retry и без паузы**; текст: «источник временно недоступен» |
| 504, read/write/connect timeout, SSE завис | Пустой с `timeout=true` |
| 429 + `Retry-After` | [ВЛ] **Немедленная ошибка источника, без retry и без паузы**; текст: «источник временно недоступен» |
| 403 | [ВЛ] Сообщение пользователю + **без retry**; ручное отключение источника, без обхода anti-bot (ADR-011/028) |
| 401 | [ВЛ] **Один** retry через warmup; при повторе — ошибка источника в тексте ответа (ADR-016) |
| 404 (URL устарел) | Пустой + **Alert: обновить Constants** |
| 301/302/307/308 | OkHttp следует; проверить cookie-jar по новому домену + обновить Constants |
| Бесконечный редирект | `ProtocolException` → пустой |
| SSL (handshake / истёк / TLS mismatch) | Пустой + **Alert: проверить сертификат** (без circuit) |
| DNS / connect refused / reset | Пустой; reset — retry 1 раз; долгий сбой — метрика + Alert |
| Прокси/MTU/IPv6 | Timeout-семейство → пустой с `timeout=true` |
| 204 / пустое тело / 200-пусто / HTML-ошибка 200 | `ParseException` → пустой; 0 результатов — легитимно |
| Ошибки парсинга контента | Пропустить элемент (ride/событие/отель), остальные проходят |
| Капча / Cloudflare / honeypot / fingerprint | [ВЛ] **Обход anti-bot не делаем** (ADR-VL-12): сообщение пользователю + Alert + ручное отключение источника |
| Юридические (Cease & Desist, ToS-баннер, платный API) | Отключить источник вручную (`source_state.enabled=false`) |
| Гео/VPN/региональная блокировка | Прокси в РБ / residential proxy |
| Маршруты внутри РФ | Не через BZD/Atlas — РЖД или российские агрегаторы |

## ~~Circuit breaker~~ — ОТМЕНЕНО (ADR-VL-04, ПРОТ-17)

- ~~По одному на каждый источник: CLOSED → OPEN → HALF_OPEN → CLOSED~~ — в MVP нет.
- ~~Порог 5 ошибок за 30 сек → OPEN на 60 сек~~ — в MVP нет.
- ~~В OPEN запросы отдаются мгновенно пустым результатом или из кэша~~ — в MVP: источник вызывается, его ошибка попадает в текст ответа; кэш (TTL 5 мин) отдаётся только с предупреждением.
- ~~Приоритет circuit > enabled~~ — в MVP конфликта флагов нет.
- ~~Перевод в OPEN: 403, капча, истёкший SSL, повторяющиеся 401, долгий DNS-сбой~~ — в MVP эти ситуации дают ошибку источника + метрику + Alert.
- Вместо breaker: per-source таймауты, `source.errors`/`AlertEvaluator` (WARN), ручной флаг `source_state.enabled` (ADR-VL-10).

## Retry

- По умолчанию **retry отсутствует**; исключения:
  - `Connection reset` — retry 1 раз;
  - `401` / cookie-сессия (BZD, TicketBus) — [ВЛ] **один** `retry warmup`, затем ошибка источника;
  - `403` — [ВЛ] retry **запрещён** (ADR-011);
  - `503`/`429` — [ВЛ] не retry и **не пауза**, ошибка источника сразу уходит в ответ (ADR-016).
- [ВЛ] Retry-попытки **одного логического запроса считаются одной ошибкой** в `source.errors` (ADR-016, ПРОТ-10).

## Warmup (cookie-сессии)

- BZD (`pass.rw.by`), TicketBus: `GET /` → создаются `JSESSIONID`/cookies + CSRF-токен (если требуется).
- Warmup выполняется при включении источника и при `401` (retry warmup).
- Cookie-jar привязывается к домену и `User-Agent`: смена UA или домена ломает сессию → fix в Constants.
- Если warmup не сохраняет cookie (200 без Set-Cookie) — диагностировать cookie-jar.

## SSE (Atlas)

- События буферизуются и обрабатываются по мере поступления; `done` без rides — легитимный пустой результат.
- Ошибка в середине потока: сохранить уже найденные rides + `error`, вернуть `partial=true`.
- Нет `done` / завис / слишком долгий поток (>30 сек / read timeout 10 сек): `partial=true`.
- Невалидный JSON, неизвестный `event:`, комментарии `:`, BOM, `\r\n` — обрабатываются, поток не роняется.
- Дедупликация по `rideId`.

## Контент и парсинг

- HTML: Jsoup + селекторы из Constants; смена вёрстки → `parse.errors > 10/мин` → **Alert: обновить парсер**.
- JSON: Jackson 3 строгий режим; для «грязных» источников включить `ALLOW_TRAILING_COMMA`, `ALLOW_SINGLE_QUOTES`, `ALLOW_NON_NUMERIC_NUMBERS`, `ALLOW_JAVA_COMMENTS`, `ALLOW_UNESCAPED_CONTROL_CHARS`.
- Кодировка: `Jsoup.parse(body, charsetFromHeader, baseUri)`, strip BOM; при сомнениях override charset.
- null в обязательных полях / пустые поля / невалидные даты / цены без валюты — валидатор `OfferNormalizer` отбрасывает элемент, остальные проходят.
- Нормализация: копейки ([BZD] ÷100), диапазон цен (min), за ночь vs за период, 12h/24h, локали, TZ Европа/Минск.
- Дедупликация после всех источников — Combiner по `rideId`.

## Метрики и алерты

- На каждую ошибку: `source.errors{source="atlas", type="500"}`.
- **Alert** при смене формата: `parse.errors > 10/мин`.
- **Alert** при 404/редиректе домена: условия «обновить Constants».
- **Alert** при SSL: «проверить сертификат».
- **Alert** при капче/Cloudflare: «источник под анти-ботом».

## Логи

- Каждый запрос имеет `request-id` — по нему прослеживается цепочка: промпт → tool → источник → парсер → ответ.
- В логах фиксируются: тип исключения, источник, URL, HTTP-код, partial/timeout-флаги, request-id.

## Fallback и сообщения пользователю

- Кэш результатов при таймауте/ошибке источника — **только вместе с предупреждением** пользователю.
- Частичные результаты предпочтительнее пустых.
- Понятные сообщения: «источник временно недоступен», «Город не найден», «Уточните станцию», «Билеты продаются за 90 дней», «Отелей рядом не нашлось», «Где именно?».
- Дисклеймеры: оплата (санкции), визы, COVID-ограничения.
