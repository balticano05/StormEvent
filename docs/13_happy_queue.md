# Хэппи пути 69–80: Очередь при нагрузке

> **Обновлено по решениям владельца** ([`25_contradictions.md`](25_contradictions.md), раздел 0.1). Помеченные `~~...~~` правила **отменены**.
> Актуально: жёсткий лимит очереди + backpressure, **FIFO без приоритетов и aging** (ADR-021), `ArrayBlockingQueue(100)`, 4–8 воркеров, дедупликация по `requestId`, переполнение → **503 QUEUE_REJECTED + `Retry-After: 5`**. Метрики — свои счётчики + `AlertEvaluator` (WARN), Prometheus не подключаем (ADR-022).

Очередь имеет жёсткий лимит + backpressure (без приоритетов).
Анхэппи-случаи — в [`15_unhappy_queue.md`](15_unhappy_queue.md).

### HP-69. Параллельные запросы разных пользователей
10 пользователей одновременно шлют запросы. Каждый в своей сессии.
Tool-ы дёргаются через **несколько производных `OkHttpClient`** от базового (ADR-014: базовый + `newBuilder()`-производные, отдельный профиль для тяжёлых источников). 10 запросов встают в очередь на пул соединений. OkHttp сам распределяет. Все получают ответ.

### HP-70. Один пользователь, 5 запросов подряд
Session store сериализует реплики по `sessionId` (запись в `session_message` в порядке поступления), [ВЛ] отмены и прерывания запросов нет (ADR-025). Пользователь видит ответы по мере готовности.

### HP-71. Очередь на LLM
~~Внутренний `Semaphore(10)` или `RateLimiter`; при переполнении — fallback на rule-based extractor~~ → **[ОТМЕНЕНО]**.
[ВЛ] Лимиты OpenRouter — через retry с backoff внутри LLM-клиента; при недоступности LLM — fallback без LLM (ADR-020/027).

### HP-72. Очередь на внешний источник
Atlas не любит высокую частоту. `Semaphore` на клиенте Atlas допускается. 20 параллельных поисков встают в очередь. Средний latency растёт, но все получают ответ.

### HP-73. Приоритезация в очереди
~~Refine-запросы идут с высоким приоритетом; `PriorityBlockingQueue`~~ → **[ОТМЕНЕНО]** (ADR-021, ПРОТ-05).
[ВЛ] Отдельного refine нет; очередь FIFO на входе, источники выбирает LLM (ADR-019).

### HP-74. Backpressure при перегрузке
Очередь >100 задач. Новые запросы отклоняются с **503 Service Unavailable + `Retry-After: 5`**.
Пользователь видит «Сервис перегружен, попробуйте через 5 секунд».
[ВЛ] Отдельного refine/поискового эндпоинта нет — отказ возвращается тем же чат-эндпоинтом (ADR-017).

### HP-75. Дедупликация в очереди
Два одинаковых `requestId` → второй игнорируется, результат отдаётся из кэша.
**Один вызов к Atlas вместо двух.**

### HP-76. Очередь на запись в session store
[ВЛ] Session store — **Postgres** (`session_message`), записи по `sessionId` последовательны; чтения не блокируются. ~~Redis/Caffeine~~ (ADR-018).

### HP-77. Плавная деградация под нагрузке
Load > 80%: агент переключается в режим «только топ-источник».
BUS — только Atlas, TRAIN — только BZD. Меньше вызовов, быстрее ответ.
[ВЛ] Механизм — `MetricsCollector`/`AlertEvaluator` с WARN + ручной флаг `source_state.enabled` (вместо автоматического breaker, ADR-020).

### HP-78. Очередь на SSE-поток Atlas
Atlas SSE-поток держит соединение 5–10 сек. Пул соединений ограничен → остальные ждут в очереди на `Semaphore`.

### HP-79. Приоритет для refine в очереди SSE
~~Refine-запросы идут вперёд~~ → **[ОТМЕНЕНО]** (ADR-021).

### HP-80. Мониторинг очереди
Метрики: `queue.size`, `queue.wait.time.p99`, `queue.rejected.count` — **собственные счётчики** `MetricsCollector`; пороги проверяет `AlertEvaluator` (лог WARN, >90% очереди).
~~Prometheus скребёт, Grafana рисует~~ → **[ОТМЕНЕНО]** (ADR-022, ПРОТ-20/21).
