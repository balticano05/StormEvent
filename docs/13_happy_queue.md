# Хэппи пути 69–80: Очередь при нагрузке

> **[ОТМЕНЕНО] Раздел не реализуется в MVP — [ADR-VL-15](decisions.md#adr-vl-15).** Очереди нет: ни `ArrayBlockingQueue`, ни воркеров, ни backpressure/`QUEUE_REJECTED`/`Retry-After`, ни приоритетов. Запрос обрабатывается в потоке HTTP-запроса, источники вызываются последовательно, клиент один.
> Ранее действовавшие правки ([ADR-VL-05](decisions.md#adr-vl-05)) заменены: FIFO, 4–8 воркеров, дедупликация `requestId` в очереди, переполнение → 503 — всё это снято.
> Документ остаётся как материал для будущей задачи (очередь/нагрузка), если решение вернётся.

### HP-70. Один пользователь, 5 запросов подряд
Session store сериализует реплики по `sessionId` (запись в `session_message` в порядке поступления), [ВЛ] отмены и прерывания запросов нет (ADR-VL-09). Пользователь видит ответы по мере готовности.

### HP-77. Плавная деградация под нагрузке
[ВЛ] ~~Load > 80%: агент переключается в режим «только топ-источник».~~ Очереди нет, автопереключения нет; при перегрузке — метрики, алерты и ручной флаг `source_state.enabled` (ADR-VL-15).
BUS — только Atlas, TRAIN — только BZD. Меньше вызовов, быстрее ответ.
[ВЛ] Механизм — `MetricsCollector`/`AlertEvaluator` с WARN + ручной флаг `source_state.enabled` (вместо автоматического breaker, ADR-VL-04).
