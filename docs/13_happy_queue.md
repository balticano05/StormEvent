# Хэппи пути 69–80: Очередь при нагрузке

Очередь имеет жёсткий лимит + backpressure + приоритеты + aging.
Анхэппи-случаи — в [`15_unhappy_queue.md`](15_unhappy_queue.md).

### HP-69. Параллельные запросы разных пользователей
10 пользователей одновременно шлют запросы. Каждый в своей сессии.
Tool-ы дёргаются через общий `OkHttpClient` (пул 5 соединений). 10 запросов встают
в очередь на 5 соединений. OkHttp сам распределяет. Все получают ответ.

### HP-70. Один пользователь, 5 запросов подряд
Session store блокирует по `sessionId`. Запросы обрабатываются последовательно.
Пользователь видит ответы по мере готовности.

### HP-71. Очередь на LLM
LLM-провайдер имеет rate limit 10 RPS. 50 одновременных extract'ов.
Внутренний `Semaphore(10)` или `RateLimiter`. Остальные ждут в очереди до 5 сек.
Если дольше — fallback на rule-based extractor.

### HP-72. Очередь на внешний источник
Atlas не любит >5 RPS. `Semaphore(5)` на `AtlasClient`. 20 параллельных поисков
встают в очередь. Средний latency растёт, но все получают ответ.

### HP-73. Приоритезация в очереди
Refine-запросы (короткие, из кэша) идут с высоким приоритетом. Новые поиски — с низким.
`PriorityBlockingQueue` перед Tool-исполнителем.

### HP-74. Backpressure при перегрузке
Очередь >100 задач. Новые запросы отклоняются с **429 Too Many Requests + Retry-After: 5**.
Пользователь видит «Сервис загружен, повторите через 5 секунд».

### HP-75. Дедупликация в очереди
Два пользователя одновременно ищут «Минск — Брест 15 июня».
Второй запрос ждёт результата первого и получает его из кэша.
**Один вызов к Atlas вместо двух.**

### HP-76. Очередь на запись в session store
Redis/Caffeine session store под нагрузкой. Запись через `Striped.lock()` по `sessionId`.
Чтения не блокируются.

### HP-77. Плавная деградация под нагрузкой
Load > 80%: агент переключается в режим «только топ-источник».
BUS — только Atlas, TRAIN — только BZD. Меньше вызовов, быстрее ответ.

### HP-78. Очередь на SSE-поток Atlas
Atlas SSE-поток держит соединение 5–10 сек. Пул соединений 5 → только 5 параллельных SSE.
Остальные ждут в очереди на `Semaphore(5)`. Timeout ожидания — 15 сек.

### HP-79. Приоритет для refine в очереди SSE
Refine-запросы, которым нужен свежий Atlas, идут вперёд новых.
`Semaphore` с `tryAcquire(timeout)`.

### HP-80. Мониторинг очереди
Метрики: `queue.size`, `queue.wait.time.p99`, `queue.rejected.count`.
Prometheus скребёт, Grafana рисует. **Alert при >50 в очереди.**
