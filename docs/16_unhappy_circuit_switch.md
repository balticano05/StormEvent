# Анхэппи пути 89–115: Отключение/включение источников

> **Обновлено по решениям владельца** ([`25_contradictions.md`](25_contradictions.md), раздел 0.1). Помеченные `~~...~~` правила **отменены**.
> **Circuit breaker в MVP НЕ реализуется** (ADR-020, ПРОТ-17): нет `circuit_state`, OPEN/HALF_OPEN, `pausedUntil`/cooldown. Вместо него — per-source таймауты, `MetricsCollector`/`AlertEvaluator` (WARN) и **ручной флаг `source_state.enabled`** (ADR-026).

Отключение источника — через ручной флаг + drain (новые запросы не идут, активные дорабатывают).
Автоматического «отключения по числу ошибок» нет: упавший источник просто возвращает ошибку, а агент упоминает её в тексте ответа.

## ~~Circuit breaker~~ — ОТМЕНЕНО (ADR-020)

Весь раздел оставлен как справочный материал для будущей версии. В MVP:
- источник не «открывается» автоматически; упавший источник даёт `SourceStatus.FAILURE` с `errorCode` (`SOURCE_TIMEOUT`, `SOURCE_UNAVAILABLE`, `SOURCE_AUTH`, …);
- каждый упавший источник **упоминается в тексте ответа** пользователю, результат остаётся частичным (ADR-011);
- реакция системы — метрика `source.errors` + WARN-алерт (ADR-022) и ручное отключение оператором.

### ~~АНП-89. Atlas лежит — открываем circuit~~ — ОТМЕНЕНО
~~Atlas вернул 5 ошибок подряд за 30 сек → OPEN, следующие 60 сек запросы не идут~~ → В MVP: таймаут Atlas (per-source) → `TIMEOUT` в ответе + предупреждение; TicketBus опрашивается параллельно и его результат попадает в ответ.

### ~~АНП-90. Circuit в HALF_OPEN~~ — ОТМЕНЕНО
~~Пробный запрос через 60 сек, успех → CLOSED~~ → В MVP: восстановление источника фиксируется по успешным метрикам; отдельной state machine нет.

### ~~АНП-91. Полуоткрытый circuit под нагрузкой~~ — ОТМЕНЕНО
~~`AtomicBoolean` на пробный запрос~~ → В MVP не применимо.

### АНП-92. BZD cookie сломался (403)
BZD отвечает 403. [ВЛ] **Сообщаем пользователю и НЕ повторяем** (ADR-011/016). Агент возвращает результаты других источников и явно пишет, что поезда/BZD недоступны.
Источник оператор отключает вручную (АНП-101).

### ~~АНП-93. Circuit открыт, но пользователь настаивает~~ — ОТМЕНЕНО
~~`forceSource=bzd`, breaker пропускает 1 запрос~~ → [ВЛ] `forceSource` не делаем (ADR-019): инструменты выбирает LLM, но retry после 403 запрещён политикой источника.

### АНП-94. Все источники домена упали
Atlas и TicketBus оба вернули ошибку. BUS-домен пустой.
**Ответ:** «Автобусы временно недоступны» (текст), сервис продолжает работать.

### АНП-95. Источник недоступен, но кэш есть
[ВЛ] Кэш (TTL 5 мин) отдаётся **только вместе с предупреждением** пользователю, что данные могут быть неполными/устаревшими.

### ~~АНП-96. Circuit не закрывается после восстановления~~ — ОТМЕНЕНО
~~TTL на OPEN 5 мин + принудительный HALF_OPEN~~ → В MVP: нет OPEN; ручное включение возвращает источник в работу (АНП-101/102).

### ~~АНП-97. Circuit по ключу эндпоинта~~ — ОТМЕНЕНО
~~`atlas:stream` / `atlas:suggest`~~ → В MVP счётчики ошибок ведём per-source-endpoint (для диагностики), но автоматических отключений нет.

### АНП-98. Retry не должен засорять метрики
Client делает до 3 retry. Считаем **1 ошибку на логический запрос**, а не на попытку (ADR-016, ПРОТ-10). Тест `SourceErrorCountTest`.

### АНП-99. Пиковая нагрузка + каскадные отказы
Все источники падают одновременно.
**Ответ:** «Источники временно недоступны, попробуйте позже» (текст), сервис не падает; alert `all sources unavailable` (ERROR).

### АНП-100. LLM недоступен
[ВЛ] Если `OPENROUTER_API_KEY` не задан или провайдер вернул ошибки — **fallback без LLM**: выбор источников по контексту/флагам, финальный текст собирается по шаблону (ADR-027). Circuit для `llm` не нужен.

## Отключение и повторное включение под нагрузкой

### АНП-101. Источник отключён вручна
Оператор вызывает `POST /api/v1/sources/atlas/disable` (за `X-Api-Key`, ADR-026). Флаг `source_state.enabled=false` в Postgres.
Tool не вызывает Atlas. Пользователь видит только результаты других источников. Метрика `source.disabled`.

### АНП-102. Источник включён обратно
[ВЛ] `enabled=true` — источник сразу возвращается в работу; сбрасывать нечего (circuit нет).

### ~~АНП-103. Включение под пиковой нагрузкой — обвал (ramp-up)~~ — ОТМЕНЕНО
~~Первые 30 сек только 10% трафика~~ → В MVP не делаем; оператор включает источник вручную и смотрит на `source.errors`/алерты.

### АНП-104. Отключение в момент активного потока
Флаг `draining` → новые запросы не идут, активные дорабатывают; поток не «убивается» (отмены нет — ADR-025).

### АНП-105. Отключение источника в момент записи в сессию
Источник выключен → агент не вызывает его инструмент и не упоминает его в ответе; в логах/метриках — `source.disabled`.

### АНП-106. Плавное отключение (drain)
Флаг `draining=true` → новые запросы к источнику не идут, активные дорабатывают. Затем оператор ставит `enabled=false`.

### АНП-107. Отключение LLM
[ВЛ] Ключ OpenRouter не задан / провайдер недоступен → fallback **без LLM**: выбор источников по контексту, финальный текст по шаблону. Функциональность снижена, сервис жив.

### АНП-108. Отключение всех источников
`atlas=false, ticketbus=false, bzd=false, ticketpro=false, belhotel=false`.
Агент отвечает текстом: «Все источники отключены, попробуйте позже». Метрика `all.sources.disabled`.

### АНП-109. Отключение очереди
Очередь переполнена (100) → новые запросы отклоняются с **503 + `Retry-After: 5`**.
Пользователь: «Сервис перегружен, подождите».

### АНП-110. Отключение сессий
[ВЛ] Session store — Postgres; если БД недоступна, новые сессии не создаются, ответ — «Сервис на обслуживании». TTL сессии — 15 мин с последнего обращения (ADR-018).

### АНП-111. Рестарт приложения под нагрузкой
Graceful shutdown: активные запросы дорабатывают в пределах graceful-таймаута, новые не принимаются. Сессии в Postgres — состояние восстанавливается после рестарта.

### АНП-112. Отключение одного эндпоинта источника
Эндпоинт упал, другие работают. Ошибка фиксируется per-source-endpoint; остальные эндпоинты используются как обычно.

### АНП-113. Включение после простоя
После включения первые запросы идут в источник и могут быть медленнее (cold start, warmup). Допустимо; при ошибке warmup — повтор через 30 сек (не падает приложение).

### АНП-114. Флаг включения не подхватился
[ВЛ] Значение `source_state.enabled` читается из БД без долгого кэша (или с коротким TTL ≤30 сек) — иначе пользователь видит устаревшее поведение.

### ~~АНП-115. Конфликт флагов `enabled` и `circuit`~~ — ОТМЕНЕНО
~~«circuit > enabled»~~ → В MVP конфликта нет: circuit не существует, приоритет флагов не нужен.
