# StormEvent — Спецификация путей (Happy Path / Unhappy Path)

Агрегатор билетов, событий и отелей. LLM-агент понимает запрос пользователя (`SearchIntent`),
параллельно дёргает внешние источники через инструменты (Tools), комбинер склеивает результаты,
ранкер сортирует, LLM пишет резюме. Любое непонимание/падение обрабатывается Guard/Clarifier/Refiner.

## Домены

| Домен | Источники | Инструмент |
|---|---|---|
| `BUS` | AtlasBus (atlasbus.by), TicketBus (ticketbus.by) | `SearchBusesTool` |
| `TRAIN` | BZD / pass.rw.by | `SearchTrainsTool` |
| `EVENT` | TicketPro (ticketpro.by) | `SearchEventsTool` |
| `HOTEL` | BelHotel (belhotel.by) | `SearchHotelsTool` |

## Поток запроса

```
Промпт → Extractor (LLM → SearchIntent) → Validator/Guard
       → Clarifier (если missing) / Refiner (если это refine)
       → Tools параллельно (CompletableFuture / виртуальные потоки)
       → OfferNormalizer → Combiner (склейка комбо) → Ranker (топ-N)
       → LLM summary → Guard (пост-валидация) → Ответ пользователю
```

## Главное правило

> Любой анхэппи путь заканчивается либо понятным сообщением пользователю,
> либо частичным результатом. Ни один не должен ронять всю сессию.

## Главные правила

1. **Refine** всегда мержит в старый интент, сохраняя контекст сессии.
2. **Очередь** имеет жёсткий лимит + backpressure + приоритеты + aging.
3. **Circuit breaker** — на каждый источник отдельно, с HALF_OPEN и TTL (приоритет: circuit > enabled).
4. **Отключение источника** — через флаг + drain + ramp-up, чтобы не обвалить при включении.
5. **Ошибка источника** ловится на своём уровне: `IOException → *ClientException → *ServiceException → Tool → пустой список`; источник изолирован — падение одного не рушит остальные.
6. **Метрики** на каждую ошибку: `source.errors{source="atlas", type="500"}`; alert при смене формата: `parse.errors > 10/мин`.
7. **Логи с request-id** — можно отследить конкретный запрос; **fallback** — кэш, частичные результаты, понятное сообщение пользователю.
8. **Любой анхэппи путь** заканчивается либо понятным сообщением пользователю, либо частичным результатом. Ни один не должен ронять всю сессию.
